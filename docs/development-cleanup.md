# 开发产物清理规则

本文是本仓库开发产物清理的唯一规则来源。清理的目标是删除能够可靠归属于本仓库、由编辑或验证过程产生且可安全重新生成的输出，同时保留发布输入、用户环境和 Agent 工作状态。

只有用户明确要求时才执行清理。全面审计不等于删除所有相关内容；无法确认归属、用途或可再生性的内容必须保留并报告。

## 请求语义

### 清理仓库内开发产物

仅审计当前 Git 工作树内部明确可再生成的临时文件和验证输出，不检查仓库外位置。

### 清理当前项目所有开发产物

“清理当前项目所有开发产物”“全面清理当前项目”或含义等价的明确请求，表示：

- 审计当前工作树，以及 `/tmp`、`/private/tmp` 和当前用户 `$TMPDIR` 中能够可靠归属于本仓库的临时输出；
- 覆盖本次及历史 Agent 会话执行编辑、格式检查、语法检查、审计和文档验证留下的同类产物；
- 删除满足本文全部归属和安全条件的可再生输出，无需对同一范围再次请求许可。

如果当前目录不是本仓库的 Git 工作树，或请求可能指向父目录中的多个仓库，必须先明确目标。

### 清理当前项目所有开发和验证残留

本仓库目前没有项目专属的本机 App、Helper、服务或其他开发安装状态。因此，该请求与“清理当前项目所有开发产物”使用相同范围。

Homebrew 的 tap、下载缓存、已安装 Cask 和应用属于用户管理的 Homebrew 或机器状态，不属于本仓库的开发验证残留，不得据此请求自动删除或卸载。

## 当前项目定义

| 项目属性 | 值 |
|---|---|
| 仓库名称 | `homebrew-tap` |
| 发布源码 | `Casks/*.rb`、`docs/*/appcast.xml`、`docs/index.html`、`README.md` |

| 仓库外审计范围 | `/tmp`、`/private/tmp`、当前用户 `$TMPDIR` 中能够通过仓库绝对路径或具体命令证明归属的临时输出 |

本仓库没有 Xcode project/workspace、DerivedData、SwiftPM 构建目录、bundle identifier、Application Support 数据或 release manifest。不得为了套用其他项目的模板而推测或新增这些定义。

## 项目归属判定

仓库内候选项必须同时满足：

- 规范化后的路径位于当前工作树内；
- 文件未受 Git 跟踪；
- 本文明确将其列为可再生内容，或具体编辑、检查命令能够证明它是临时输出；
- 删除不会移除发布输入、用户手工编写内容或其他不可再生信息。

仓库外候选项必须至少具备一项强证据：

- 内容或元数据记录当前工作树的规范化绝对路径；
- 本仓库实际执行过的命令明确创建该精确路径；
- 当前任务的命令记录能够将输出路径与本仓库直接对应。

目录位于临时位置、最近被修改、被 `.gitignore` 忽略，或名称包含应用名、`homebrew`、`tap`、`Codex`、`Agent`，都不能单独证明归属。不得使用模糊名称搜索批量删除。

## 可删除内容

满足全部归属和安全条件后，可以删除：

- 工作树内的 `.DS_Store`；
- 语法、格式、审计、XML 或 HTML 验证明确生成的未跟踪临时输出；
- 编辑器或脚本为当前仓库创建、且不承载用户内容的临时副本；
- 系统临时目录中能由仓库绝对路径或具体命令证明归属的同类输出。

`.gitignore` 只能作为线索，不能单独证明文件可以删除。不得使用 `git clean` 代替逐项判断。删除符号链接时只处理链接本身，不跟随链接递归删除目标。

## 禁止删除内容

无论是否与本仓库有关，均不得删除：

- `Casks/` 下的 Cask 定义；
- `docs/` 下的 appcast、站点文件和本清理规则；
- `README.md`、`LICENSE`、`.gitignore`、`.git/` 及其他受版本控制内容；
- 未跟踪但无法证明为可再生输出的文件；
- Homebrew tap clone、Homebrew 下载或 API 缓存、下载的 DMG/PKG、已安装 Cask 和应用；
- 其他仓库或应用的发布文件、缓存和临时输出；
- Codex、ChatGPT 或其他 Agent 的 conversation、thread、session、配置、Skill、认证状态和工具配置；
- `~/.codex/`、`~/.agents/`、ChatGPT/Codex 的 Application Support 数据，以及仓库内 `.engramory-memory/`；
- 用途、所有权、项目归属或可再生性无法确认的系统文件。

Agent 对话记录可以作为调查线索，但记录本身永远不是清理目标。

## 执行流程

1. 确认当前 Git 根目录确实是本仓库，并读取本文件。
2. 检查工作树状态；已有修改和未跟踪文件均视为用户内容，除非精确满足本文的可删除条件。
3. 根据请求语义确定仅审计工作树，还是同时审计允许的系统临时目录。
4. 规范化候选路径；`/tmp` 通常指向 `/private/tmp`，统计前必须去重。
5. 为每个候选项记录归属证据、删除或保留理由，并在删除前统计占用空间。
6. 只删除同时满足项目归属、可再生性和非用户内容要求的精确目标。
7. 使用同一口径重新统计，计算每项实际释放空间，并再次扫描相同范围。
8. 再次检查 Git 状态，确认未修改或删除受版本控制文件以及任务开始前的工作区变更。
9. 确认 Agent 对话、配置、认证状态、Skill 和 Memory 未被扫描或修改。

不得使用 `sudo`，不得修改文件权限或所有权，也不得停止 Homebrew、应用或其他进程来扩大清理范围。

## 结果报告

清理完成后必须报告：

- 删除的主要目录或文件；
- 每项清理前大小、清理后大小和实际释放空间；
- 去重后的总实际释放空间；
- 保留的候选项及原因；
- 无法检查的范围和剩余风险。

完成结论应表述为：所有能够可靠归属于本仓库、可安全重新生成的开发和验证输出均已清除；发布源码、Homebrew 用户状态、共享缓存、Agent 对话和无法可靠归属的内容未处理。不得声称系统中不存在任何与本仓库有关的痕迹。
